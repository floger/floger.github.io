1. PSI 称用内部 AI 研究系统证明了 Aaronson–Ambainis 猜想，Lean 通过检查
Physical Superintelligence（PSI）11 月 6 日发布研究页，称其内部研究系统在运行中调用非公开的 Anthropic 模型，在第三天得到 2008 年提出的 Aaronson–Ambainis 猜想的完整证明，且该证明被 Lean 证明助手逐步检查通过；随后系统又两次改进结果，最终版本同样被 Lean 接受。该猜想关系量子计算机在随机输入上能否相对经典计算实现指数加速。斯坦福的 Blanc、Docter、Strassle、Tan 此前解决了该猜想的特例，PSI 称他们已阅读这份证明并给出评论、正在撰写面向专家的简版阐述。
值得看：这是“AI 做数学”从解题走向解决公开问题的一个具体案例，且带形式化验证，比单纯的评测分数更可核查。但这是公司自报，尚未见同行评审；形式化陈述与原猜想是否完全一致，仍需人工确认。
PSI 研究页（含论文与 Lean 形式化链接）；Lean 形式化仓库
2. Meta 把 Muse Wonder 训练的专用模型下放到 Muse 与 Meta AI
Meta 11 月 6 日在研究博客宣布，用 Muse Wonder 训练的专用模型已上线 Muse 与 Meta AI，并把 Active Memory 与 Active Focus 两项能力带给消费端。官方给出四组数字：Muse 上“忘记关键信息”减少约 2.4 倍；出现意外阻碍时完成日常任务的表现在改善约 67%；Active Memory 评测中正确使用关键上下文的比例从 76% 升到 90%；Personal Superintelligence Index 从 38% 升到 47%。
值得看：值得注意的不是分数，而是“区分临时信息与长期信息、跨时间推理、判断信息是否过期”被当成可训练目标——这正是长期记忆型 Agent 的真实难点。以上均为厂商自报指标，评测集未公开。
Meta 官方研究博客（指标为厂商口径，未独立复现）
3. OpenCode 推出 Browse：让 Agent 用你本机已登录的真实浏览器
OpenCode 上线 Browse，由一个 MCP 服务器和一个 Chromium 扩展组成，让 Agent 驱动本机的真实浏览器（Chrome、Edge、Brave、Arc、Helium、Vivaldi、Opera 等），复用自己的标签页、登录态与扩展。官方说明：用 Playwright 打开并操作标签页，支持截图与录屏，标签在后台分组；遇到登录、两步验证、付款等敏感步骤会把标签交还用户，点 Continue 后继续。文档同时标注了站点 allowlist 等边界控制。
值得看：这是“Agent 需要登录态”的现实解法——不是把密码交给模型，而是把交互权在关键时刻交回给人。团队评估浏览器 Agent 时，应重点看敏感步骤的移交机制和白名单，而不是成功率数字。
OpenCode 产品页；GitHub 仓库
4. Amp 推出 Spaces：用一个“指挥官 Agent”派生并协调多个 Agent
Amp 11 月 6 日发布 Spaces：一个 space 就是与单个 Agent 的对话，而这个 Agent 的职责是为用户派生并协调其他 Agent，用户不再需要自己建线程、理线程。官方给的使用例包括：把一个功能拆成多个线程推进、一个人从一个 space 完成服务账号上线与后续监控、把代码库切成 16 个区域做安全评审并在另一个线程里核对每条发现。官方称已用这套方式搭建 Spaces 本身。
值得看：多 Agent 的产品形态正在从“编排 DSL”转向“一个会分工的入口 + 可追踪的产物”；判断这类产品好不好用，看的是子任务之间的状态是否可见、结论是否可复核。
Amp 官方发布说明（厂商自述使用体验）
5. Anthropic 发布科研使用报告：Claude Science 的单次任务约等于两倍人工工时
Anthropic 11 月 5 日发布《AI for scientific discovery: How researchers use Claude》，按经济度量框架分析科研场景的会话：Claude Science 上的单次会话所包含的工作，若不用 AI，所需人工时间接近 Claude 与 Claude Code 上的两倍；Claude Science 会话中超过 80% 的工作估计需要博士级训练（约 20 年教育），其他界面约为 50%–70%；Claude Science 中超过 70% 的会话处于高度自主状态，Claude 为 23.7%、Claude Code 为 64.1%。报告还称使用强度与任务的能力评分高度相关。
值得看：这份报告把“AI 帮科研”拆成可比的工时与自主度指标，比笼统的“提效”更有用；但它基于平台自身会话数据，样本与估算方法需在原文核对。
Anthropic 官方报告（含 PDF，方法为厂商自建框架）
6. Frontier Model Forum 发布网络类越狱评级框架 v1.0，公开征求意见到 12 月 21 日
Frontier Model Forum 11 月 5 日发布《Jailbreak Rating Framework for Frontier Cyber Threats》1.0 版，用四个维度给成功绕过的网络类越狱定级：能力增益、能力范围、部署难度、发现难度，目标是让不同机构对同一个越狱的风险判断可比，从而优先修补高风险问题。论坛同时开放公开征求意见，截止 2026 年 12 月 21 日，并计划将反馈并入后续版本。
值得看：安全团队内部评审越狱样本时常缺少统一量纲，“靠感觉排序”导致资源错配；这套四维打分可以直接当内部模板试跑，再按自家业务调整权重。
FMF 官方发布（行业框架，非标准或法规）
7. Claude Code 文档更新云环境配置：环境变量、组织共享与归档
Claude Code 文档新增“Configure cloud environments”一节，说明云会话的环境如何配置：可设置环境变量、在 CLI 中选择环境、归档环境，并支持组织共享的环境；同时文档把 Cloud environments 与 Self-hosted environments、Sandbox environments 并列为不同层级的环境形态。
值得看：云会话从“每次重新装依赖”走向“可复用、可共享的环境”，是企业落地的必要条件；这也意味着密钥与网络访问策略需要跟着环境一起纳入治理，而不是留在个人终端。
Claude Code 官方文档（文档为准，具体可用范围随套餐与版本变化）
