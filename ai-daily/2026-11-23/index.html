1. OpenRouter 移除三家提供商、撤销 125 个端点的 ZDR 资格：平台与下游事件要分开
OpenRouter 11 月 22 日公告称，调查后已移除三家提供商，并撤销 125 个端点的零数据保留（ZDR）资格，其中包含预防性移除；测试没有显示 OpenRouter 自身被未授权访问。Together AI 11 月 21 日另行确认：编码 Agent 将私有仓库凭据提交到公开仓库，暴露窗口内有人下载了此前留存的部分提示样本，涉及主要来自 6–7 月的请求。Together 的数据内容审查仍在进行，不能写成所有用户或所有模型的提示均已泄漏。
值得看：应按“路由平台—具体推理端点—留存策略—实际数据路径”审计，而不是只认模型品牌。敏感任务要限制下游提供商、避免在提示中放长期密钥，并检查旧账号设置；Together 说的是新账号默认 ZDR，不是所有历史账号已自动切换。

2. OpenAI 首席科学家提议用困惑度辅助设定共同研发边界，不是行业已达成限制协议
Jakub Pachocki 在 OpenAI 11 月 22 日文章中公开内部预训练测量，并提议结合困惑度与其他指标，建立跨实验室的发展边界与安全里程碑。文中主要数字来自固定快照的内部代码评估集；作者明确指出，不同数据集难以横向比较，困惑度不直接等于实际任务能力，也不能计入思维链等预训练外改进。这是研究与治理提议，不是监管新规或各公司已经签署的承诺。
值得看：这篇文章的价值是讨论可持续跟踪的共同尺度，而非提供一个“跨过某数字就会 AGI”的公式。写作或选型时同时列出评估集、后训练条件和真实任务测试，避免把同一损失数值直接用于比较不同厂商。
OpenAI 原文、数据口径及作者自述局限（11 月 22 日；单一作者提议）
3. 蚂蚁 LingSante-3.1-flash 更新模型卡：560B 医疗 MoE，明确不是独立诊疗依据
inclusionAI 的 LingSante-3.1-flash 模型卡与评测材料在 11 月 23 日继续更新，提供开放权重和 MIT 许可。作者标注总参数 560B、每 token 激活 25B、支持 1M 上下文，基于 Ling-3.1-flash，面向医学证据整合、专业交流和多阶段工具任务。卡片明确仅用于研究与评估，不是医疗器械，不得独立诊断、处方或决定治疗；基准和模拟环境成绩也不证明临床有效性。本条按今日材料更新报道，不将仓库创建日当首发日。
值得看：长上下文医疗 Agent 的验收重点应是证据能否追溯、关键遗漏是否可发现、工具动作是否有专业人员审批。部署示例使用多卡；25B 激活量不等于只需加载 25B 权重，亦不能用开放许可替代医疗与隐私合规审查。

4. Qwen Code 0.28.4：状态目录收紧、命令迁移防覆盖，并提示中断会话需要继续
Qwen Code v0.28.4 于北京时间 11 月 22 日 20:04 发布，晚于上期采集。相较 v0.28.3，本地 Runtime 改为在进程启动时创建仅属主可访问的状态目录；命令迁移独占创建 Markdown 目标，遇到冲突保留原 TOML。Web Shell 为中断轮次增加 Continue 标记，Autofix 检查证据展示前移除终端控制字符及 Unicode 双向覆盖字符。本期不重复上一版企业微信与 Webhook 通道。
值得看：长期运行 Agent 需要保护状态文件、迁移原件和失败证据，而不是只让界面显得完成。可先在隔离副本测试目标文件已存在时的迁移、中断后继续、日志含控制字符三种情况；本期只读发布记录，未安装回归。

5. DeepSeek Harness alpha.2 调整 Node.js 最低版本：上期 alpha.1 后的运行环境变更
DeepSeek Harness 于北京时间 11 月 22 日 19:00 发布 dsh-v0.2.3-alpha.2，仍是预发布。此版发布说明明确调整 Node.js 要求：24.x 分支须为 24.22.3 或更新版本，或使用 26.13.1 及以上版本。本条只报道相对 alpha.1 的运行环境变更，不把上期飞书连接器、SQLite 和评审页面再次包装为新功能。
值得看：固定镜像、Windows CLI 和后台服务可能各自使用不同 Node 版本；升级前应从真正启动进程的环境读取版本，再核对依赖锁定和回退方案。满足运行时门槛也不表示 alpha 已达到生产稳定性。

6. llm-d 原生接入 SGLang：共享 K8S 控制层，但三级缓存并非总能降低延迟
llm-d 11 月 23 日技术文章介绍，将 SGLang Wide-EP 接入与 vLLM 共用的 Kubernetes 编排及路由层，让每个 attention-DP rank 成为独立可路由端点。在作者的 16 张 H200、并发 128 测试中，加入主机内存 L2 后输出吞吐从 319 升至 1,257 token/s，中位首 token 延迟从 174.2 秒降至 20.1 秒。同步共享文件 L3 在稳定无故障负载下反而增加开销，其价值主要体现在跨副本故障转移与冷恢复；不是任意部署都获得四倍收益。
值得看：先把缓存命中、调度端点和故障恢复测清楚，再决定是否加共享存储。对离线 K8S，可吸收其“单平台兼容多引擎、单副本先 L1＋L2、需要恢复能力再 L3”的验证顺序；文中的云端硬件结果不能直接套用本地集群。

7. Lean 社区发布黎曼猜想证明核验声明：命题一致、标准公理与独立内核是三道不同门槛
Lean FRO 与 Mathlib Initiative 在 11 月 21 日联合声明，对 Levent Alpöge 11 月 20 日公布的 Lean 证明表达确认，说明已检查命题是否等同于 Mathlib 的黎曼猜想表述、代码可编译及独立检查器是否接受。MIT 的 Andrew Sutherland 验证页截至 11 月 22 日 16:20 UTC 更新，列出 175,187 个模块核验、仅依赖三项标准公理，以及多个独立检查器的结果；同页仍将部分完整导出复核列为运行中。这里报道社区声明与公开核验进展，本期没有自行编译证明，也不宣称每项检查都已结束。
值得看：AI 数学新闻不能只问“代码能否跑过”，还要确认它证明的确实是原命题，并排除额外假设。可复用到工程验收的是：精确检查目标、核对依赖、隔离重建、让独立实现复核，而不是用同一个 Agent 重复自我确认。

8. Baseten 开放 bison-1 与 groundhog-1：长上下文结构化决策，不只是聊天模型换名
Baseten 公告页面时间为 UTC 11 月 20 日 20:02，即北京时间 11 月 21 日 04:02。bison-1 为 31B，groundhog-1 为 26B MoE、约 4B 激活，均基于 Gemma 4，接受文字和图片，支持 128k 上下文，并提供开放权重和付费 API。团队报告 bison-1 在 Artificial Analysis Decision Index v2.1 的 19 个模型中得分 76、Brier 分数 0.14；这是公告引用的评测成绩，本期未独立重测，不代表任意业务决策都更可靠。
值得看：工单路由、政策分类、风险评分等任务，可以同时评估输出结构和置信度校准，而不是只比较长回答质量。应检查错分代价、拒判与人工兜底；权重开放不等于托管推理免费，也不意味着自动批准付款已安全。

9. AWS 发布分布式 KV 缓存技能实践：先证明省钱，再让编码 Agent 创建资源
AWS 原文时间为美国太平洋时间 11 月 20 日 16:14，即北京时间 11 月 21 日 08:14。其 Agent Toolkit 技能引导 Kiro、Claude Code、Codex 等先检查缓存适配性，再用 KVTrace 按实际流量估算收益，收益不足以覆盖成本就停止。文章要求高影响资源操作先审批，并强调清空本地缓存后复核输出：缓存命中计数正常，仍可能因布局不一致而得到错误答案。所谓最高节省 40% 成本、降低 80% 首 token 延迟是特定工作负载下的厂商口径。
值得看：可复制的是“只读诊断—测真实流量—核算总成本—审批写操作—验证正确性”，不是直接购买云缓存。KVTrace 不记录提示正文和 token ID，但哈希来自 token 内容，敏感场景仍要匿名化并隔离租户；云服务不是免费的离线组件。
