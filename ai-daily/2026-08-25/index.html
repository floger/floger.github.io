AI 日报：2026-08-25

今日重点：AI 产业的竞争继续从“模型参数”转向 Agent 的可移植性、长程执行、训练效率、端侧部署和真实科研验证。以下内容优先采用官方博客、GitHub Changelog、Hugging Face、arXiv 及国内垂直媒体，信息截至 18:00（中国标准时间）。

1. Agent Plugins 1.0 试图让同一套技能和 MCP 配置跨客户端复用
GitHub 发布 Agent Plugins 1.0：插件可以在 VS Code、Copilot CLI 和 Copilot app 之间共享，统一打包 skills、MCP server、命令、规则和 hooks，并可通过 marketplace 分发。GitHub 还说明，企业可以用现有的 managed settings 管理插件白名单。
💡 值得看：如果插件标准真的被多个客户端采用，Agent 生态可能从“每个平台重新写技能”转向可移植的能力包，但 MCP 权限治理会成为前置条件。
🔗 GitHub Changelog；Agent Plugins 规范入口（🟢 官方来源）
2. OneDayAgent 把长程任务拆解、记忆和验收放进同一个 harness
arXiv 论文 OneDayAgent 提出面向开放式日常任务的长程执行 harness：将请求拆成有边界的子任务，在上下文压力下维护执行记忆，并对最终交付物进行验证和修复。在 AgentIF-OneDay 的 104 个任务上，论文报告 GLM-5.2 后端得分 0.821；作者同时强调，结果仍局限于该基准，且实现没有工作区隔离。
💡 值得看：论文把“模型会不会回答”改成“系统能否完成并验收交付物”，也直接暴露了长程 Agent 的安全边界问题。
🔗 arXiv 原论文；arXiv cs.AI 最新列表（🟢 论文原始来源；指标为作者报告）
3. Agent Lightning v1.0 将“部署中的 harness”纳入 Agent 强化学习训练
论文介绍 Agent Lightning v1.0：训练引擎通过代理连接任意 Agent harness，重点处理 retokenization、样本合并、优势计算、损失归一化和调度等问题。作者报告，在约 6000 个训练样本和相对有限的计算资源下，Qwen3.5-9B 在 SWE-bench Verified 上从 41.8% 提升到 56.4%；该结果仍需外部复现实验。
💡 值得看：训练不再只围绕模型本体，工具调用、上下文压缩和运行时轨迹正在成为可优化对象。
🔗 arXiv 原论文；Microsoft Agent Lightning GitHub（🟢 官方论文与代码入口）
4. EASy 用“能力—成本”感知的编排器调度异构执行器
arXiv 论文 EASy 提出 milestone-plan-act 工作流：先拆分里程碑，再建立依赖图、选择合适的执行器，并并行执行互不依赖的步骤；训练奖励同时考虑任务正确性、执行效率和轨迹完整性。论文在数学、具身决策和深度研究基准上报告了更好的性能—效率折中。
💡 值得看：企业 Agent 的核心问题不是每一步都用最强模型，而是在质量、延迟和成本之间动态做选择。
🔗 arXiv 原论文；arXiv cs.AI 列表（🟢 论文原始来源；结论待更广泛复现）
5. HyperAgent 用工具 Schema 超图减少 Agent 的盲目 API 探索
HyperAgent 将工具表示为输入 Schema 到输出 Schema 的有向超边，先构建任务相关工具图和依赖感知的 Task DAG，再根据当前状态补齐缺失输入所需的工具支持子图。论文在 AppWorld 实验中报告，相比基线可提升任务完成率，并减少冗余 API 调用、LLM 交互和 token 消耗。
💡 值得看：把工具之间的输入输出依赖显式化，可能比单纯给模型更长的工具说明更能提升复杂工作流的可靠性。
🔗 arXiv 原论文；arXiv cs.AI 列表（🟢 论文原始来源）
6. Hugging Face 公布 ICML 论文开放复现挑战：19 天尝试 2226 篇论文
Hugging Face 总结 ICML 2026 Open Reproductions：1221 名参与者在 7 月 15 日至 8 月 2 日间发布 6816 份 Trackio logbook，尝试复现 2226 篇论文，评估了 35908 条 claims，并公开了部分 Agent trace 数据。报告也记录了 Agent 因循环、尺度误读和单位错误产生的“伪验证”。
💡 值得看：AI 科研 Agent 的价值不只在于能跑实验，更在于能否留下可审计的代码、数据、轨迹和失败证据。
🔗 Hugging Face 官方总结；公开复现画廊（🟢 官方项目与公开数据）
7. Liquid AI 发布 LFM2.5-2.6B，主打端侧 Agent 和工具调用
Liquid AI 在 Hugging Face 介绍 LFM2.5-2.6B：模型上下文扩展到 128K，并通过工具使用、网页搜索和 harness 轨迹训练 Agent 能力。官方测试称其在部分指令遵循和工具使用基准表现突出，并报告在 M5 Max 上约 220 tokens/s、在 Ryzen AI Max+ 395 上约 113 tokens/s；这些是厂商测试结果。
💡 值得看：端侧 Agent 的竞争焦点正在从“能否对话”变成“能否低延迟调用工具且不把数据送上云”。
🔗 Hugging Face / Liquid AI；LFM2.5 DSpark 推理优化（🟢 官方发布；性能为厂商数据）
8. GitHub 将 Agent 运行能力扩展到 Slack 和 Microsoft Teams
GitHub Changelog 介绍，Copilot 可在 Slack 公共预览中由 @GitHub 发起 Agent 会话，用于规划变更、调查问题、执行代码任务并创建 Pull Request；在 Microsoft Teams 中，参与者还可以共同查看和引导同一 Agent 会话。企业权限、沙箱策略和额外审批仍决定实际可执行范围。
💡 值得看：Agent 正从 IDE 内工具变成团队协作里的异步成员，但“谁授权、谁负责、谁审查”必须跟着进入聊天界面。
🔗 GitHub Slack 公共预览；GitHub Teams 更新（🟢 官方来源）
9. 国内：小米发布玄戒 O3、O100、D100 三款自研芯片，向全场景 AI 延伸
机器之心产业资讯报道，小米在 8 月 24 日技术沟通会上发布玄戒 O3、O100、D100 三款芯片，覆盖不同终端和计算场景，报道将其解读为从手机芯片向全场景 AI 基础设施延伸。当前公开信息主要来自国内垂直媒体，芯片规格和量产节奏仍应以小米官方披露为准。
💡 值得看：国产 AI 竞争正在从模型发布扩展到端侧芯片、推理成本和软硬件协同，值得持续跟踪实际出货与生态支持。
🔗 机器之心产业资讯；小米官方入口（🟡 国内媒体报道，规格待官方补充）
10. 国内：阿里视频大模型 Wan3.0 上线，视频生成竞争进入稳定交付阶段
机器之心产业资讯报道，阿里视频大模型 Wan3.0 于 8 月 24 日正式上线，报道中的行业评价集中在稳定性、真实感和画面质感。具体模型能力、开放范围、接口价格和许可证信息应以阿里官方产品页面或模型仓库为准，当前不把媒体评价等同于独立测评结论。
💡 值得看：视频模型的下一轮竞争不只是单条样片效果，而是长时一致性、可控编辑、成本和商业化交付。
🔗 机器之心产业资讯；阿里云 AI 产品入口（🟡 国内媒体报道，官方细节待补）
