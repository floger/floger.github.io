AI 日报：2026-11-04

采集于 2026-11-04 · 共 10 条 · 优先最近 24 小时，补充最近 72 小时内未收录进展；各条注明原始发布日期。厂商性能数据与研究结论均保留来源口径，“值得看”属于编辑分析。

1. 腾讯发布 Hy4 正式版，权重开源仍待后续
11 月 4 日，IT之家与第一财经报道腾讯发布 Hy4。腾讯称新版本扩展训练规模、增强长程任务能力，并引入视觉与电脑操作能力；IT之家报道其已接入腾讯云、OpenRouter 及多款腾讯产品。模型权重和系统卡片为后续发布计划，不能据此认定权重已经开放。
值得看：选型时可把视觉输入、跨应用操作和 API 可用性分开验证；“发布模型”与“可下载权重”会对应完全不同的部署方案。
IT之家报道；第一财经记者报道（发布事件交叉确认；性能为厂商口径）
2. Mundo 世界模型把少量影像转为可交互的机器人仿真环境
商汤 11 月 4 日介绍大晓机器人与南洋理工大学 S-Lab 的 Mundo 项目。项目页展示从 1 至 12 张上下文图像构建场景，以三维代理记录布局、场景程序定义质量和摩擦、物理引擎计算运动，再用视频模型渲染结果；未被相机覆盖的区域仍由模型推断补全。
值得看：它把画面生成与物理状态分开维护，可作为机器人训练数据和仿真环境的技术参考；演示效果尚不能替代真实机器人任务成功率验证。
商汤项目介绍；Mundo 原始项目页（研究团队披露，未独立复现）
3. Google 与 Mercor 发布 PLE：用真实工程交付物评测 Agent
11 月 3 日，Google 与 Mercor 公布 Physical-Engineering’s Last Exam：覆盖机械、电气、土木、结构四类共 85 项长程任务，开放其中 29 项及评分工具。按双方公告的私有测试集口径，最佳配置平均得分为 48.3%；任务需先通过硬性安全与可行性检查才能获得成本效率分。
值得看：这套评测展示如何把规范、文件版本和硬性验收条件写进 Agent 任务，适合借鉴到工程交付验收；分数只适用于对应测试设置。
Google 原文；Mercor 联合发布说明（双方联合研究口径，不是独立复现）
4. OpenAI 研究：安全评测与生产行为可能存在反向落差
OpenAI 11 月 3 日研究比较六款模型在 Respecting Warnings 评测和匹配的 Codex 生产案例中的行为，报告评测成功率比对应生产样本低 10.2 至 37.4 个百分点。作者明确指出匹配是近似的，样本不能代表所有部署；目标提示干预可改变评测成绩，但不等于真实安全能力同步提升。
值得看：评测需要核对任务目标、授权边界及生产样本分布；仅靠一张安全分数表，难以预测 Agent 在业务环境中的行为。
OpenAI Alignment 原始研究（单一研究团队披露，未独立复现）
5. Snowflake CoWork 增加团队配置与可对话看板
Snowflake 11 月 3 日介绍 CoWork Profiles、Dashboards 与定时 Automations 的组合：管理员按团队配置可用 Agent、技能和连接器，用户可围绕看板追问或定时生成报告。公告将 Dashboards 标为公开预览，并说明 Profile 和定时任务沿用用户权限，不扩大数据访问范围。
值得看：企业 Agent 的实用入口正在结合数据看板、任务调度和权限治理；可参考其“按角色配置、按用户权限运行”的设计。
Snowflake 官方公告（单一厂商披露，具体开放范围以产品账户为准）
6. 美团 LongCat-2.5 强化原生多模态与长程 Agent 训练
美团 11 月 2 日技术文章公布 LongCat-2.5：总参数 1.6 万亿，每个 token 激活约 480 亿参数，强化原生视觉和长程智能体任务。文章披露将真实 Agent 失败轨迹转为可复现训练任务，并介绍国产算力上的长上下文训练与 W4A4 推理优化；新华网 11 月 3 日报道了此次发布。
值得看：技术细节覆盖失败轨迹、可验证测试与跨工具框架训练，适合研究如何把线上失败案例转为持续改进材料，而不只比较榜单。
美团技术团队原文；新华网报道（原日期 11 月 2 日；技术指标为厂商披露）
7. SenseNova 6.8 Flash 发布，主动交互演示仍有版本边界
商汤日期为 11 月 2 日的公告发布 SenseNova 6.8 Flash 正式版，介绍跨任务协作及 Web、SVG、Blender、PPT 等交付形式；第一财经于 11 月 3 日报道。官方特别注明主动交互案例基于小浣熊内部研发版，动态 Blender 设计依赖本地环境与用户多轮交互，不能将全部演示视为开箱即用能力。
值得看：评估设计 Agent 时应检查最终文件能否继续编辑、需要哪些本地工具，以及演示功能是否在当前产品版本开放。
商汤原始公告；第一财经报道（原日期以正文 11 月 2 日为准）
8. NVIDIA 开源 Attribution，串联分布式 AI 作业的故障证据
NVIDIA 11 月 2 日技术博客介绍开源 Attribution，通过确定性规则关联日志、指标和调度状态，输出根因候选、受影响节点和症状链。系统包含 REST 服务和 Python 参考编排组件，可对接 Slurm、Kueue、Loki、Kubernetes 日志等；证据不足或多因匹配时保留不确定性。
值得看：跨节点报错常是同一故障的连锁症状。这套工具的价值在于可追溯证据与可定制规则，适合 GPU 集群运维团队评估。
NVIDIA 官方技术文章（原日期 11 月 2 日；单一厂商披露）
9. OpenAI 披露 Pando：为大量并行编码 Agent 扩展 Git 后端
OpenAI 11 月 2 日介绍内部 Git 后端 Pando，在保持 Git 协议与客户端兼容的同时，按分支协调写入并复用 packfile。公司称生产环境推送延迟中位数降低近 80%，每天交付接近 1 PB 的 Git 数据；跨多个分支读取不保证同一时刻的全库快照。这是内部基础设施披露，文章未宣布对外提供 Pando 服务。
值得看：编码 Agent 并行度上升会增加仓库读取、分支推送与 CI 压力；文章具体解释了缓存复用和一致性取舍。
OpenAI 工程原文（原日期 11 月 2 日；性能数据为公司自报）
10. OpenAI 上调软件漏洞赏金，新增报告质量与长期参与奖励
OpenAI 11 月 2 日更新 Security Bug Bounty：ChatGPT、Codex、API Platform 等核心产品的严重漏洞基础奖励最高 3 万美元，特殊严重发现仍可获最高 10 万美元，叠加奖金最高约 17.2 万美元。新规则还引入报告质量、长期参与和重点活动奖励；这些上限不代表所有报告均可获得。
值得看：计划强调可复现证据与影响说明，可作为安全团队改进漏洞报告质量的参考；参与范围与奖励条件需阅读原计划。
OpenAI 官方规则更新（原日期 11 月 2 日；奖励政策的一手来源）
