1. Gemini 推出任务执行更新：预约、账单和购物开始进入同一助手
Google 11 月 17 日宣布，基于 Gemini 4 Hydrogen 的任务更新开始向美国、日本、韩国、加拿大、澳大利亚和印度免费推送，部分高级能力先在美国推出。官方展示了代打电话预约、连接密码管理器分析账单、通过 Google Pay 购物等流程，并称已连接超过 60 款应用。任务运行在专属硬件隔离虚拟机中，购买前设计为请求确认或预授权；官方同时承认任务仍可能失败，某些网站需要用户接手最后一步。可用性受地区、运营商和功能限制，并非全球所有用户同步开放。
值得看：这次新进展不是上期的语音选项，也不只是模型发布，而是账号、支付、执行环境和审批的产品整合。设计个人 Agent 时，可以照着拆出“信息权限—执行沙箱—消费上限—关键动作确认”四层边界。
Google 官方公告及地区、权限限制（11 月 17 日）
2. Qwen Code 0.28.0：接入 Qwen4-Max，并推进共享 Agent 循环与钉钉通道
Qwen Code 官方 11 月 17 日发布 v0.28.0。更新日志列出 Qwen4-Max 原生 effort 档位、缓存 TTL 和图像 detail 支持；无头会话、Ink TUI 和子 Agent 默认使用共享 Agent 循环；托管通道新增钉钉适配，并修复 Webhook 拒绝处理、会话中断历史保留及文件类型检查等问题。本条是模型发布之后的工具适配新进展，不重复前期 Qwen4-Max 模型参数与跑分。
值得看：做企业编码助手，不应只确认模型名能选，还要验证推理档位、缓存设置、跨会话消息和审批是否在不同入口保持一致。开源代码不等于模型调用免费；本期仅阅读发布记录，没有安装或执行新版本。
Qwen Code 官方版本与完整变更记录（11 月 17 日）
3. Isomorphic Labs 宣布 50 亿美元 C 轮融资，继续扩张 AI 药物设计引擎
Isomorphic Labs 11 月 17 日宣布完成 50 亿美元 C 轮融资，由 Greenoaks 与 Sequoia Capital 联合领投，a16z 等参与，Alphabet 继续追加投资；既有投资者亦参投。公司表示将扩展自有药物设计引擎 IsoDDE 和 AI 设计的治疗候选管线。金额与用途均为公司公告口径，融资并不意味着候选药已经证明临床有效。
值得看：AI 制药的资金正在同时支持模型能力和药物管线。跟踪这类企业应把融资、候选分子进展、临床阶段与真实疗效分开，而不是把模型投入直接等同于药物成功。
Isomorphic Labs 官方公告（11 月 17 日） · 公司完整新闻稿（美通社；同源补充，非独立核实）
4. Hugging Face 将语言模型推理切换至 OpenRouter，原有自带服务商密钥受影响
Hugging Face 11 月 16 日宣布，Inference Providers 的语言模型请求由自有路由切换至 OpenRouter，按价格、速度和可靠性选择服务商，并在失败时尝试其他服务商。官方称现有调用代码可保持不变，但语言模型将通过 Hugging Face 账号计费，不能再使用自带的服务商 API key；图像、视频和音频仍走原有路径。可在设置中禁用指定服务商；价格按服务商计费，Hugging Face 不额外加价。
值得看：对国内开放权重模型用户，这比“又接入一个模型”更重要：请求可能经由不同服务商，计费、数据流向和缓存命中都需重新核对。公司采购或敏感业务应先设置服务商白名单，而不是因 API 兼容就直接迁移。
Hugging Face 官方迁移说明与 breaking change（11 月 16 日）
5. NVIDIA 发布 Nemotron for Science：把化学数据、后训练配方与科学工具组合起来
NVIDIA 11 月 16 日推出 Nemotron for Science，围绕 Nemotron 3.5 Super VL 提供科学评估、开放化学数据与后训练配方。LitmusBench v0.2 包含近 5 万道化学问题，可用于训练和评估；官方介绍了反应信息抽取、实验协议设计以及连接 CUDA-X 工具的科学 Agent 用例。模型与数据已在 Hugging Face 提供。应用效果为公司及合作机构报告，本期未复现。
值得看：与前期单独报道基础模型不同，本次重点是领域数据和工具闭环。实验室落地应先验证数据许可、工具输出与实验可执行性，不宜把化学题分数直接当成药物发现成功率。
NVIDIA 官方科学 Agent 公告（11 月 16 日）
6. AWS 将 NVIDIA Dynamo 纳入 HyperPod 推理，给出多节点与预填充/解码分离部署路径
AWS 11 月 17 日发布技术文章（页面时间换算为北京时间 18 日），介绍 SageMaker HyperPod Inference 对 NVIDIA Dynamo 的支持：可自带 DynamoGraphDeployment，或通过 InferenceEndpointConfig 的 dynamoSpec 部署，使用 vLLM、SGLang 或 TensorRT-LLM。文章演示 GLM-5.3 多节点部署与 KV 感知路由；在特定 Qwen3-235B、16 张 H200、输入 4,000/输出 200 token 和延迟约束下，官方测得分离部署最高吞吐为聚合部署的 2.05 倍。该数字只代表所述测试，不是通用加速保证。
值得看：材料明确拆开了模型权重、KV 传输、网络和调度的责任。给国内开放模型做私有推理时，也应先验证节点间通信和真实前缀复用，再决定是否值得拆分 prefill/decode；HyperPod 是计费云服务，不是免费的本地部署方案。
AWS 官方架构、配置和基准条件（11 月 17 日）
7. AgentCore 工程案例：不把 23 MB JSON 塞进上下文，改用引用、分页和结构摘要
AWS 11 月 17 日文章（北京时间 18 日）介绍 Flightscape 机组排班 Agent 的优化：完整数据存入 S3，持久状态保存轻量引用；大型列表先返回样本与结果句柄，按需分页；大型字典用字段描述压缩。官方在约 23 MB 数据上测试，5 问会话 token 从约 28.95 万降至 8.29 万，平均 trace 延迟从 15.4 秒降至 3.1 秒；100 问样本的降幅分别为 64% 和 69%。两组样本不能混为同一项结果，且未独立复现。
值得看：不必先换更便宜的模型，也能从工具返回值下手。可迁移的最小做法是“完整结果放存储，模型先看数量和样本，需要时按句柄取页”；采用前仍需补访问控制、结果过期与存储费用核算。
AWS 官方实现、代码片段与分组结果（11 月 17 日）
8. 边缘多智能体论文：把 Agent 选择、检索与资源分配放进同一个约束问题
11 月 16 日上传 arXiv 的《Multi-LLM Agentic AI at the Edge》提出由监督 Agent 调度多个边缘工作 Agent，覆盖串行、并行流程及两级重试。在时延和服务质量约束下，联合优化 Agent 选择、检索选择与带宽或服务时间分配，以减少系统能耗。作者报告仿真节能结果，并在基于 Qwen、Llama 的 ToolQA 系统上验证任务成功率；正文注明论文已被 IEEE Transactions on Mobile Computing 接收，当前为作者版本。本期阅读 HTML 正文，未复现。
值得看：多 Agent 的成本不只由模型单价决定，还包括通信、检索和失败重试。做内网边缘部署时，可以借鉴其约束思路先列出时延、质量和资源预算，不必照搬整套优化算法。
arXiv 日期与摘要（11 月 16 日） · 作者论文 HTML 正文
