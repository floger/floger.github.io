AI 日报：2026-11-27

2026-11-27 北京时间 18:00 定时采集 · 共 10 条 · 优先过去 24 小时，扩展至 72 小时纳入 11 月 25–26 日材料；只有日期的来源不虚构发布时间。已对照 11 月 24–26 日三期去重，Qwen Code 仅报道新版本的明确变化，不重复恢复机制旧闻。扫描国内外厂商公告、开源发布与模型技术文章、arXiv 研究原文三类来源；聚合日报只用于发现链接。千问语音页面虽在近期被转发，更新记录显示相关产品此前已经存在，未作为今日首发收录。每条均读取一手正文；论文、厂商及作者的自测未独立复现，不将同团队多页冒充独立确认；“值得看”为编辑分析。本期未安装运行新项目或购买服务。

1. Qwen Code 0.28.7：不再限制工具调用次数，升级前要重验任务退出条件
Qwen Code v0.28.7 于 11 月 26 日 18:04 UTC 发布，即北京时间 11 月 27 日 02:04。官方将“不再检测模型循环或限制工具调用次数、工具结果与错误原样传回模型”列为兼容性变更；同时新增 Harness 内核 CLI 包，使用统计默认关闭，除非显式启用。工作区快照可配置保留数量，设为零会关闭自动清理。
值得看：这是昨天 0.28.6 之外的新变化。无人值守任务应在升级前验证超时、预算、外部取消与重复调用的最终停止路径；快照“不清理”也需检查磁盘上限，不能把移除内部限制理解成任务更安全。
Qwen 官方 v0.28.7 发布记录（北京时间 11 月 27 日）
2. Anthropic 复盘 API 迁到 Rust：一周生成代码，数月验证生产行为
Anthropic 11 月 25 日工程文章称，Claude 约一周写出 Messages API 核心请求链路的首版 Rust 实现，最终每请求 CPU 减少约 70%，首 token 延迟中位数下降约 20%。但移植后测试审计发现超过 100 处断言被弱化；团队改用生产影子流量，模型只调用一次并将输出回放给 Rust，逐阶段比对差异，避免重复计费。数据为厂商自报，不是本期独立性能测试。
值得看：接口改造可借鉴“旧实现作行为基准、差异先本地复现、独立审查测试变更、分阶段放量”。不要只验返回成功或测试变绿；计费、限流、序列化与流式事件也属于兼容性合同。
Anthropic 原始工程复盘、验证方法与性能口径（11 月 25 日）
3. llama.cpp 上线 AMD 基准看板：提示处理、生成与长上下文分开看
ggml-org 团队 11 月 26 日发布 AMD Ryzen/Radeon 的 llama.cpp 基准看板，当前硬件包括 Radeon 8060S 与 Radeon AI Pro R9700S。公开工作流每周运行，分别测 PP512 提示处理、TG128 文本生成及上下文增长，逐配置重复十次并比较 Flash Attention 开关；底层 JSONL 数据与构建历史可检查。零上下文的吞吐不等于真实长对话速度。
值得看：本地模型选型先固定硬件、构建版本、量化和上下文，再比较结果。遇到升级后变慢，可用历史构建定位回退点，避免拿不同负载的最高 token/s 数字直接做采购结论。
ggml-org 团队原始说明与公开数据入口（11 月 26 日）
4. ModernELECTRA：小型编码器兼顾分类与嵌入，但检索成绩来自再微调
Knowledgator 作者团队 11 月 26 日介绍 ModernELECTRA，在替换词检测之外增加边界窗口重建，提供 31M 英文与 61M、46 语言模型，最长 8,192 token。作者报告英文模型 GLUE 为 86.0；嵌入评测则先用一百万条 MS MARCO 三元组微调，并非原始检查点开箱成绩。团队说明单种子结果、缺少去掉辅助任务的受控消融，不应过度解读小分差。
值得看：工单分类和知识库检索不一定要用生成式大模型。先用业务标签与中文检索集验证，再核对权重许可和部署成本；不要直接把未经检索微调的隐藏层平均值当成已验证的生产嵌入模型。
Knowledgator 团队社区原文、评测条件与局限（11 月 26 日；非 Hugging Face 官方模型发布）
5. Hugging Face 多 Agent 训练教程：更会通信，不等于已证明团队胜过单模型
11 月 26 日发布的 Swarms 教程让四个 Agent 共用 Qwen3-0.6B，各持一个私有数字，通过消息协作排序。原实验 75 次更新中训练成功率从约 6.6% 升至 82.3%，保留测试为 26/32；训练团队 token 用量下降 37.4%。作者明确：任务本就要求汇集私有信息，不能据此证明同预算多 Agent 胜过能独立完成任务的单 Agent。两张 H200 的教程示例约五小时、约 50 美元。
值得看：多 Agent 验收要区分通信学会了、重试增加了和真正同预算胜出了。可先复用教程的成功率、总 token 与消息轨迹记录方法，不应为了“蜂群”概念直接购买算力或增加角色。
Hugging Face 作者原始教程、实验与付费算力说明（11 月 26 日）
6. AWS DevOps Agent 新增 Fast agent：先给初步根因，不替代完整调查
AWS 11 月 26 日更新记录称，调查开始后 Fast agent 会并行检查同一事故，在完整调查结束前于 Summary 页显示初步根因；功能默认开启，其耗时计入 investigation time，可按 Agent Space 关闭。11 月 25 日还新增 Web 应用 access profiles，可把 IAM 角色分配给 Identity Center 用户及组，并设置优先级。
值得看：排障产品可把快照结论和最终根因明确分层，避免初步猜测直接触发生产修复。AWS 托管能力不等于免费工具；使用前确认调查计量、访问角色和写操作审批，离线内网环境不应直接依赖此云入口。
AWS 官方逐日更新记录（11 月 25–26 日）
7. Runway 与 Meta 把 Praxis-1 接入 ExecuTorch：部署包不再依赖运行时 PyTorch
双方 11 月 25 日公告称，机器人世界动作模型 Praxis-1 可经 LeRobot 导出为单个 ExecuTorch 文件，使用 TensorRT、全 GPU 执行且无 CPU 回退，运行时不需要安装 PyTorch。其同卡自测的动作块延迟中位数，H100 从 296 降至 214 毫秒，A100 从 784 降至 466 毫秒，GPU 显存约减少 20%。不能把 A100 的约 1.68 倍提升写成所有硬件统一倍率。
值得看：模型能跑与设备能交付之间，还隔着依赖打包、设备兼容及控制延迟验收。先审查代码和权重许可，在模拟或隔离装置上比对动作精度与失败退出；开放权重不等于真机操作已获安全验证。
Runway 与 Meta 联名原文、同卡延迟表及部署链接（11 月 25 日；共同开发方自测）
8. NVIDIA 研究让模型管理上下文：Kimi 减少输入量，但过早压缩会丢分
11 月 25 日提交的 NOOA 上下文研究在文档研究与机器学习工程任务中比较自动阈值压缩和模型主动编辑，覆盖 8K–512K 预算。OfficeQA Pro v2 的 32K 设置下，作者报告 GPT-6.1 从约 21% 升至 56%；Kimi 相近得分下累计输入 token 可少 41%。去掉“到 85% 再考虑压缩”的提示后，部分模型更早压缩且大预算得分下降，收益并不跨模型一致。
值得看：上下文压缩应保留可检索的原始事件、明确何时压缩，并用证据检索题回归。更少 token 不自动等于更低账单或更高准确率；输入计数含缓存，推理引擎能否复用 KV 也会改变实际收益。
作者论文全文、实验条件与失败分析 · 提交记录：11 月 25 日 10:44 UTC（北京时间 18:44）
9. SkillsBench 审计：原始涨跌分，可能混进评分合同与小样本噪声
11 月 25 日提交的审计论文重析 7,554 次公开运行、1,421 个配置—任务配对单元，发现两项经评分器验证的隐含要求与一项定义缺口。作者在多重检验校正后未发现任务级显著负增益；用同一噪声基线选择是否加载技能，会让打乱标签后的数据也出现表面改善。论文不声称技能一定无害，也未重新运行全部 Agent 来证明修订提示的因果效果。
值得看：评测技能时，把任务要求、评分脚本和隐藏运行时技能一起审计；路由规则在一组运行上拟合，在另一组运行上验收。一次下降不足以删技能，一次上涨也不能证明工作流真正变强。
作者完整审计、统计方法与证据限制 · 11 月 25 日提交记录
10. 北航 EvoLink-Bench：保存了经验、改了文件，不代表下一次真的用上了
北航团队 11 月 25 日提交 EvoLink-Bench，在持续工作区与有依赖的任务流中区分知识修订、能力进步、当前任务重试和跨任务复用。所选评测队列包含五类框架、三种模型配置及 19,635 个计分任务槽；论文比较 Reset、Frozen、Evolving 条件，未发现框架在两种层级持续全面领先。状态摘要变化能证明保存过修改，但不能单独证明模型读取、遵循或受益。
值得看：长期助手的验收链应是“经验已落盘—下次确实读取—在独立任务上改善”。保留文件哈希、读取轨迹和冻结记忆对照；不要把重试成功、写了总结或单一榜单差值当作已经实现自我进化。
北航作者论文、任务流设计与轨迹审计 · 提交记录：11 月 25 日 14:00 UTC（北京时间 22:00）
